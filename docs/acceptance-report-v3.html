Headline defects (P0) — root cause and fix

DefectRoot causeFix
D1
Stale OPEN RiskReview blocked verification		Triage returned early on a SAFE verdict, so the risk review raised against the NGO's earlier, wrong documents was never superseded; verification read only the newest open review; no API listed reviews. Registration also loaded the document-analysis runner with require(), which returned no export, so re-analysis never started.A clean re-analysis now closes the triage review it opened and resolves its alerts (never admin- or agent-raised reviews); verification weighs all open reviews; GET /api/admin/risk/review lists them; analysis starts via dynamic import; NGOs get “Replace your documents” with a prefilled form.
D2
Field-evidence photo sync returned 500		Private uploads ignored STORAGE_PROVIDER=cloudinary and wrote to the read-only serverless filesystem (EROFS); the route hid the cause behind a generic 500.Cloudinary authenticated private storage; structured error codes (413/415/503/409); client-id idempotency; signed, expiring, per-viewer photo links that re-check access on every fetch.
D3
RFP upload / extraction returned an empty 500		Document-parser modules failed to load on serverless before the handler ran; model/storage failures surfaced as bare 500s; the Claude schema exceeded the API's union-type limit.Lazy parser loading; JSON errors with codes and a retryable FAILED state; Claude → Gemini → rule-based extraction with per-field confidence; manual entry; union-free Claude schema.
D4
Milestones stayed UNFUNDED after full reconciliation		Payments were recorded with no milestone link and nothing allocated reconciled money to milestones; allocation existed only for the legacy Proposal model.Reconciled money is allocated to milestones in delivery order (or the milestone the donor chose) inside a row-locked transaction; milestone funding status, admin allocation approval, contract and project FUNDED.
D5
UTR-based reconciliation not possible		Sandbox mode discarded the supplied UTR; the reconciliation sweep did no UTR matching.UTR stored and normalised in every mode, duplicates refused per payer account; reconciliation matches bank-statement lines by UTR and amount; unmatched lines go to an exception queue with manual match.

Previously not built — now implemented

  • NGO team invites for Program Manager and Field Worker (hashed, expiring, single-use tokens; revoke/resend; field workers see only their tasks).
  • Admin Finance, Auditor (read-only) and Support roles with distinct permissions; donor-team Finance role.
  • Break-glass support access: reasoned, time-boxed (≤ 60 min), audited, revocable grants.
  • Tamper-evident audit log: database-enforced append-only hash chain, live verifier and export verifier.
  • Operator dead-letter queue with one-time replay for failed jobs.
  • NGO registration save-and-resume drafts; NGO expense/utilisation recording per contract milestone.
  • Stored impact reports, donor re-engagement (renewal / next opportunity), consent-filtered impact stories.
  • Admin-triggered re-verification (review-due) workflow; structured FCRA-required field; admin shortlist approval.
  • AI call telemetry and admin fault injection; notification channel preferences with fallback and delivery log.

Notes, limits and environment

  • All data is synthetic. Payments are SANDBOX/manual-test records; no real money moved and no real NGO, company, PAN, CIN or UTR was used.
  • AI: document and RFP extraction ran on Claude (Anthropic) in this run. Without a model key the platform falls back to labelled rule-based extraction and template drafts — never invented values.
  • External delivery was not exercised live: WhatsApp (Twilio) and email providers were not configured, so notification tests verify the in-app delivery, the opt-out, the fallback order and the delivery log, where external channels are recorded as PROVIDER_NOT_CONFIGURED. Razorpay live checkout was not used; webhook handling was verified with signed test payloads.
  • Production rollout: apply the additive migrations with `prisma migrate deploy`. Do not deploy with the repo's current `npm run build`, which runs `prisma db push --accept-data-loss` (pre-existing risk noted in CLAUDE.md).
  • Production needs STORAGE_PROVIDER=cloudinary with CLOUDINARY_* keys for private uploads (the cause of D2), RAZORPAY_WEBHOOK_SECRET, and ANTHROPIC_API_KEY and/or GEMINI_API_KEY for AI extraction.
  • UI: the platform was redesigned to a light theme (homepage, admin console, NGO and donor portals); every figure on screen is read from the database.
  • Known minor UI gaps (not acceptance criteria): the donor feedback widget does not re-display the saved choice after reload; NGO claim cards do not show the method text.
